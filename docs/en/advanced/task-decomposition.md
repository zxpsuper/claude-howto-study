# Task Decomposition

## Learning Objectives

Learn how to break down complex tasks into small steps that Claude can handle.

## Why Decompose?

Claude performs best when dealing with clear, well-defined small tasks. Complex tasks often tend to have errors or miss details.

## Decomposition Strategies

### 1. Top-down Decomposition

Start with the big goal, gradually refine:
1. What do we want to do?
2. What major parts are needed?
3. What steps are in each part?
4. What specifically needs to be done in each step?

### 2. Decompose by Phase

Software development lifecycle:
1. Requirements analysis
2. Solution design
3. Implementation
4. Testing
5. Deployment

### 3. Decompose by Functional Module

- User authentication
- Data management
- UI components
- Utility functions

## Example: Building a Blog

Don't:
> "Help me make a blog system"

Instead, decompose like this:

1. "Help me design the data structure for a blog system"
2. "Based on this data structure, create database schema"
3. "Implement CRUD API for blog posts"
4. "Create blog list page"
5. "Create article detail page"
6. ...

## Practice

Choose a project you want to do and practice decomposing it into small tasks.
