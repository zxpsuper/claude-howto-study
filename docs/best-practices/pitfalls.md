# 避坑指南

## 学习目标

了解使用 Claude 时的常见陷阱以及如何避免。

## 常见陷阱

### 1. 盲目信任代码输出

❌ 错误做法：直接把 Claude 的代码用到生产环境

✅ 正确做法：
- 仔细阅读每一行
- 理解代码做了什么
- 运行测试
- 检查边界条件
- 安全审查

### 2. 提供太少上下文

❌ "帮我修复这个 bug"

✅ "我在做 X 功能，运行 Y 命令时出现了 Z 错误。这是相关代码：[代码]，这是错误信息：[错误]"

### 3. 试图一次做太多事情

❌ "帮我重写整个应用，加上用户认证、支付、管理后台..."

✅ 拆分成小任务，一个一个来

### 4. 忽略 Claude 的错误

如果 Claude 明显在胡说八道：
- 停下来，重新评估
- 可能需要换个提问方式
- 或者换个任务
- 有时重新开始一个新对话会有帮助

### 5. 提示词过于模糊

❌ "写个好网站"

✅ "用 React + TypeScript 写一个博客首页，要有 hero section、文章列表、页脚。使用 Tailwind CSS。"

## 红灯警告信号

注意这些信号：
- Claude 变得越来越啰嗦，但不说实际内容
- Claude 在重复自己
- Claude 犯明显的事实错误
- Claude 道歉但继续犯同样的错误

当这些发生时，是时候重新调整策略了。
