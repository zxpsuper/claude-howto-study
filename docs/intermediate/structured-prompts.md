# 结构化提示词

## 学习目标

掌握如何使用结构化提示词来获得更准确、更一致的输出。

## 为什么需要结构化？

当任务变得复杂时，简单的对话式提示词可能不够有效。结构化提示词可以：
- 明确 Claude 的角色
- 提供清晰的步骤
- 确保输出格式一致
- 减少误解

## Markdown 结构化

使用 Markdown 标题和列表来组织你的提示词：

```markdown
# 角色

你是一名资深的 TypeScript 开发专家。

# 任务

请帮我重构这段代码，使其更符合 TypeScript 最佳实践。

# 输入代码

[粘贴你的代码]

# 要求

1. 添加类型注解
2. 使用更现代的语法
3. 添加必要的注释
4. 保持原有功能不变

# 输出格式

请按以下格式输出：

## 原代码问题分析

[列出发现的问题]

## 重构后的代码

```typescript
[代码]
```

## 改进说明

[解释做了哪些改进]
```

## XML 风格的结构化

对于更复杂的任务，可以使用 XML 标签：

```xml
<system>
你是一名代码审查专家。审查时要关注：
- 代码质量
- 潜在的 bug
- 性能问题
- 安全性
</system>

<context>
这是一个 React 项目，使用 TypeScript。
</context>

<code>
[代码]
</code>

<instruction>
请提供详细的代码审查报告，格式为 Markdown。
</instruction>
```

## 练习

尝试用结构化提示词让 Claude 帮你完成一个相对复杂的任务。
